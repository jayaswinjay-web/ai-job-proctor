# Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | Repo layout per prompt section 4 (/agent, /client, /infra, /models, /voice, /eval, /docs) | Matches the source-of-truth architecture. |
| 2 | Self-hosted LiveKit Server (not LiveKit Cloud) | Prompt requires self-hostable, deployable in an Indian cloud region. |
| 3 | Python 3.11+ agent worker; livekit-agents framework | Prompt stack default; do not reimplement WebRTC. |
| 4 | vLLM (GPU) primary, llama.cpp (CPU/edge fallback), 4-bit quant (AWQ/GPTQ/GGUF) | Prompt stack default; cost-aware, Indian cloud region deployable. |
| 5 | Whisper-family streaming STT fine-tuned for Indian English/Indic | Prompt stack default; Indic capability. |
| 6 | Streaming TTS fine-tuned on licensed Indian voice data (male + female) | Prompt stack default; DPDP Act 2023 consent provenance in /voice/PROVENANCE.md. |
| 7 | Postgres + Redis + pgvector (or Qdrant) | Prompt stack default. |
| 8 | Desktop launcher starts Postgres, API, kiosk, admin, camera and two Python local voice services | One-click start; verified end-to-end 2026-11-15. Local voice server (:8095) is required before the local agent (agent registration on ws://localhost:7880) can be dispatched. The local agent reads repo `.env` itself so the desktop icon's `cmd` environment doesn't need to carry `LIVEKIT_URL` explicitly. |
| 9 | Kiosk points to local LiveKit Server; voice agent is Python local agent (not TS/LiveKit Cloud agent) | Prompt requires fully-offline operation; the rebranding is `voicehire-interview` in both the local Gemma/LiteLLM backup or Python local agent. |
| 10 | `start-all-lib.ps1` probes both `InterNetwork` and `InterNetworkV6` (Vite binds `::1` , API binds `0.0.0.0`) | Prevents the "Admin/Kiosk never came up" launcher bug observed 2026-11-15. |
| 11 | Fully offline deployment (verified 2026-11-15, after hardening pass): EVALUATION_PROVIDER=rules + LLM_PROVIDER=mock (deterministic; withFallback target for every use of the LLM) + STT_PROVIDER=whisper-http with AI_BASE_URL=http://127.0.0.1:8095/v1/audio/transcriptions (OpenAI-compatible faster-whisper endpoint added to the local voice server) + TTS_PROVIDER=browser (voice path uses Piper) + ALLOW_BROWSER_VOICE_FALLBACK=false + VOICE_MODE=livekit with LIVEKIT_URL=ws://localhost:7880 | Local Whisper + Tamil LLaMA + Piper all run on CUDA on the same machine. Docker/Postgres/LiveKit all run on 127.0.0.1. Server-side transcribe round-trip proven offline: Piper -> /v1/audio/transcriptions -> faster-whisper returned the exact spoken phrase. LLM_PROVIDER=livekit had remained set with a blank LIVEKIT_INFERENCE_URL (would have defaulted to agent-gateway.livekit.cloud for report generation) - switched to mock. Anything beyond this swap remains remote. |
| 12 | Kiosk CSP connect-src no longer allows https://*.livekit.cloud; only loopback/LAN endpoints are reachable from the page. User-facing strings reference the *local* voice service, not LiveKit Cloud. | Closes the last external origin the page permitted. |
| 13 | Local agent (scripts/local-livekit-agent.py) is NOT a free-chat wrapper: it runs the scripted intake flow (language/job choice -> consent -> BASIC_DETAILS via the local VoiceHire backend's /agent/* callback API), mirroring apps/voice-agent 1:1, with PHRASES copied byte-exact into scripts/voice-agent-phrases.json. Conversation copy is authored script, not model output; the engine (rules) owns scoring. | The previous agent free-chatted through a bare Tamil LLaMA and never asked a real question. Verified against the local API: session created, consent directives spoken in Tamil, BASIC_DETAILS advanced to ask_previous_work. |
| 14 | Turn detection is 'vad' + no-op local LLM (LocalTamilLLM returns an empty assistant chunk instantly). The livekit-agents framework still fires LLM inference per committed turn; the empty chunk silences it instead of crashing (ChatChunk.id is required by pydantic) or double-speaking with the directives. | The interview must be deterministic; LLM output must be impossible on this path. |
| 15 | Interruptions are disabled (turn_handling.interruption.enabled=false): candidate audio is discarded while the agent speaks (by design, same as the cloud agent). The candidate must answer after the agent finishes its line. VAD sees frames; STT receives silence during agent speech. | Without this, candidate speech during a line was transcribed into garbage or dropped - the 'AI did not speak clearly and after speaking something it stopped' symptom was this plus (a) batch STT not wrapped for streaming, (b) ChatChunk pydantic validation error, (c) sync httpx blocking the event loop. |
| 16 | Local Tamil ASR is the known weak link offline: whisper-tiny and whisper-small both fail to recognize PIPER-synthesized Tamil reliably (e.g. 'தமிழ்' -> 'தாமி'/'பொன்று அனையில்'); the tiny model is in use. A larger model (large-v3-turbo) was attempted but the model CDN (cdn-lfs.huggingface.co) is unreachable from this network, and VRAM is capped at 6 GB. | Synthetic-speech results do NOT indicate human-mic performance (natural speech is far more intelligible to Whisper); expect the live kiosk to work better than tests show, and verify with a real microphone. |
